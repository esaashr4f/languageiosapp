# Content format

The authoritative description of what the tools accept. BRIEF.md section 4 gives the intent; this file gives the exact rules enforced by `tools/lint-content.ts`.

## Folder

```
content/<iso>/
  meta.json       name, endonym, iso, family, region, era, status, scripts, typology, depth, hook, difficulty,
                  organising_idea, sample (one example), translit_optional (true only for Latin-script originals)
  dossier.md      phonemes, script and transliteration scheme, paradigms with sources, disputes, base variety
  sources.json    { "sources": [ { id, citation, url?, used_for, access } ] }
  syllabus.json   { lang, parts: [ { part, title, summary } ], lessons: [ { id, part, order, slug, title, point, requires, introduces } ] }
  glossary.json   { "abbreviations": { "ACC": { name, plain, tag } }, "terms": { "term": "plain definition" } }
  STATUS.json     { "lessons": { "<id>": { "state": "planned|drafted|verified|done" } } }
  vocab.json      generated by `npm run build:reference`
  VERIFY.md       results of each verification pass
  lessons/<PP>-<OO>-<slug>.md
```

Lesson ids are `<iso>-<PP>-<OO>` (two-digit part and order; order restarts at 01 in each part). The syllabus is the source of truth: a lesson's front matter must repeat its `title`, `requires` and `introduces` exactly.

## Lesson file

```
---
id: lat-03-02
lang: lat
part: 3
order: 2
title: "The accusative: marking what is acted on"
point: Mark the object of a verb and read sentences in any word order
requires: [lat-02-01]
introduces: [accusative]
confidence: verified
sources: [ag1903, wiktionary]
---
```

`confidence` on the lesson is the weakest label of anything in it that matters. Quote any title containing a colon.

Parts 1 to 7 use the full template: these `##` sections, in this order (bracketed ones optional):

`The idea` · `How it is built` · `Examples` · `Where it applies` (required in parts 2 to 7) · `Watch out` · [`Reference table`] · `New words` · [`Connections`] · `Exercises` · `Worked answers`

Parts 0, 8 and 9 are free-form but still obey the block rules and the 400-word minimum.

Limits: 500 to 1,200 prose words (up to 1,800 in parts 2 to 7) (headings, paragraphs and lists; block contents are not counted; under 400 is an error). Parts 2 to 7: 6 to 12 examples, 15 to 30 new words. Parts 1 to 7: 5 to 10 exercises as one numbered list, and the same number of worked answers as one numbered list.

No raw HTML. No bare Markdown tables. Files must be Unicode NFC.

## Blocks

### Example

```
:::example
orig: Puella rosam amat.
translit: (omit only when meta.translit_optional is true)
morphemes: puell-a ros-am ama-t
gloss: girl-NOM.SG rose-ACC.SG love-3SG
literal: Girl rose loves.
translation: The girl loves the rose.
note: The endings, not the order, say who loves whom.
source: constructed
confidence: constructed
preview: SBJV
:::
```

- `morphemes` and `gloss` must have the same number of space-separated words, and each word the same number of `-` or `=` separated pieces. Use `.` to join several meanings carried by one piece (`NOM.SG`).
- Grammatical categories are in CAPITALS and must be in `glossary.json`. Lexical meanings are lower case; join multi-word meanings with `.` or `_` (`go.out`). Gloss the pronoun "I" as `1SG`, never as a bare capital letter. Proper names keep normal capitalisation (`Marcus`).
- Each abbreviation has a `tag`. An example may use the abbreviation only in or after the lesson whose `introduces` lists that tag, unless the example names it in `preview:` (comma-separated) and the note or surrounding prose flags it as a preview.
- `source` is `constructed` or a citation (work and passage). `confidence: attested` needs a citation; `constructed` needs `source: constructed`. A constructed sentence is never labelled `verified`.
- `literal` is optional. `preview` is optional.

### Table

```
:::table
caption: First declension, puella
confidence: verified
source: ag1903 §41
| Case | Singular | Plural |
|---|---|---|
| Nominative | puella | puellae |
:::
```

### New words

```
:::vocab
puella | - | noun | girl | puellae, f.
amō | - | verb | love | amāre, amāvī, amātum
:::
```

Fields: headword | transliteration (or `-`) | part of speech | meaning | optional principal parts or notes. A headword is introduced once per guide; `vocab.json` records the lesson.

## Verification files

`VERIFY.md` has one section per part and pass: date, who checked (fresh subagent or main), counts of forms, glosses, claims checked, corrected and still open, and the list of corrections.

## Where it applies, and Watch out (parts 2 to 7)

`Where it applies` maps every context in which the construction is correct, including the less obvious ones, each with an example (in the Examples section or inline) or a pointer to a later lesson. `Watch out` lists the places where using it seems natural but is wrong: show the wrong version (marked with an asterisk, e.g. *\*Puella est videt*), say why it fails, and give the right version. Wrong versions are prose, never `:::example` blocks.

## Review lessons

Syllabus entries with `"review": true` (slug `review` at the end of parts 2 to 7, `review-midway` in the middle of long parts) are progress checks. They introduce no grammar and no required vocabulary. Sections: `## Passage` (a connected text to translate, attested where one fits the level, otherwise constructed; given as `:::example` blocks line by line or as plain text with the analysis in the answers), optionally `## Before you start` (what the review covers, with lesson pointers), then `## Exercises` (8 to 25: translate the passage, build sentences, find and fix errors, explain a form) and `## Worked answers` (same number, each showing the reasoning and naming the lesson that teaches the point). Words not yet taught may appear only if glossed in place.
